```text

```

---

# 2. Development Rules

Before writing or modifying code:

1. Read `PRD.md`.
2. Read `UI_UX.md`.
3. Read `CONTENT.md`.
4. Read `TASK.md`.
5. Inspect the existing project structure.
6. Inspect existing dependencies.
7. Do not overwrite working code unnecessarily.
8. Do not invent missing personal information.
9. Do not add features outside the documented scope.
10. Keep components reusable and data-driven.

If documentation conflicts:

```text
Product behavior → PRD.md

Visual presentation → UI_UX.md

Portfolio content → CONTENT.md

Implementation order → TASK.md
```

---

# 3. Important Workflow Rule

Do NOT attempt to implement the entire portfolio in one large step.

Work phase by phase.

After completing a phase:

```text
1. Verify the implementation.
2. Fix errors.
3. Run the application.
4. Check responsive behavior.
5. Run build when appropriate.
6. Mark completed tasks in TASK.md.
7. Continue to the next phase.
```

Update tasks:

```text
[ ] Pending

[x] Completed
```

Do not mark a task complete until it is actually implemented.

---

# 4. Definition of Done

A task is considered complete only when:

- Implementation exists
- No obvious runtime error exists
- Layout works on desktop
- Layout works on mobile
- No horizontal overflow exists
- Content follows `CONTENT.md`
- Design follows `UI_UX.md`
- Existing functionality is not broken
