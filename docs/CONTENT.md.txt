
## Full Title

```text
WHS Digital — Stock Opname & Warehouse System
```

## Category

```text
Warehouse Management System
```

## Short Description

```text
A digital stock opname and warehouse system designed to improve inventory counting, verification, and warehouse operations.
```

## Overview

```text
WHS Digital digitalizes stock opname workflows that would otherwise rely heavily on manual processes.

The system manages warehouse data, inventory tags, stock counting, recount workflows, user verification, progress monitoring, and reporting through a centralized web application.
```

## Problem

```text
Stock opname involves large amounts of inventory data, physical counting, verification, tag management, and progress tracking.

Manual workflows can make it difficult to monitor counting progress, identify recount requirements, track responsibility, and consolidate results efficiently.
```

## Solution

```text
WHS Digital provides a centralized digital workflow where inventory tags can be generated, scanned, counted, verified, monitored, and reported through a web-based system.

QR and barcode-based workflows connect physical inventory activities with digital records.
```

## Key Features

```text
QR / Barcode Tag System
Warehouse Management
Inventory Tag Management
Stock Counting
First Count Workflow
Recount Workflow
```

# 51. Content Source of Truth Rule

OpenCode must follow these rules:

1. Use this document as the source of truth for portfolio content.
2. Do not invent missing personal information.
3. Do not invent experience.
4. Do not invent statistics.
5. Do not invent project links.
6. Do not invent social links.
7. Do not expose confidential project information.
8. Use `null` for unavailable links/data.
9. Hide UI elements whose required content is unavailable.
10. Keep content separated from presentation components.

If `CONTENT.md` conflicts with placeholder content inside UI components:

> `CONTENT.md` wins.

If `UI_UX.md` defines visual presentation:

> `UI_UX.md` wins for presentation.

If `PRD.md` defines product behavior or scope:

> `PRD.md` wins for product requirements.
